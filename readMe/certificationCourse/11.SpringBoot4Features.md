# What's new in Spring Boot 4
- Released in November 2025
- Spring Boot 4 is based on Spring Framework 7
## Key Themes
- Faster 
  - Runs on modern Java with improved startup time and lower memory usage
- Leaner 
  - A new modular design reduces classpath bloat 
- Safer
  - Null safety support and updated security to reduce runtime risks
- Enhanced Cloud Readiness
  - Default Kubernetes probes out of the box and enhanced observability support
## Categories of change
1) Modernization and Ecosystem Alignment
2) Developer Productivity
3) Runtime and Performance
4) Cloud readiness and Observability
## Breaking Changes Reminder - History
- In 2023, Spring Boot 3 introduced major breaking changes
- Package name changes: from javax. * to jakarta.*
- Migrating from Spring Boot 2 to Spring Boot 3 was A LOT OF WORK
- Many projects delayed the migrating to Spring Boot 3 due to level of effort
## Migrating to Spring Boot 4 is MUCH easier
- This is an incremental upgrade with very few breaking changes
- Your existing Spring Boot 3 knowledge still applies: DI, IoC, REST APIs
- Our course code still works... minor changes needed
- pom.ml version: <version >4•0.0</version>
- Minor updates for AOP Maven dependency and Jackson 3 packages
## Spring Boot 4 - Incremental Upgrade
- Modern upgrade across the entire Spring ecosystem
- Builds on Spring Framework 7
- Java 17+ as the baseline (Java 21 / 25 recommended)
- Ecosystem upgrades: Hibernate 7, Junit6, Jackson 3, Tomcat 11...
## Key features in Spring boot 4
- First-class API versioning

- Null safety with JSpecify

## Key Feature #1: First-Class API Versioning
- Version APIs via path, header, query, or media type
- No more custom versioning logic or filters
- Consistent versioning strategy across teams
- A clean, built-in solution that makes API versioning simple
## Key Feature #2: Jackson 3
- Jackson 3 is now the default JSON library for Spring Boot 4
- Package rename
  - com. fasterml.jackson renamed to tools. jackson
  - Affects code only if you manually use Jackson classes
- JsonMapper is Jackson 3's preferred API
  - Spring Boot 4 auto-configures a JsonMapper bean
- Impact on our course
  - Only our REST API PATCH example needs a small update... due to manually using Jackson classes
  - Normal REST JSON handling works the same
## Key Feature #3: Null-Safety with JSpeci
- What is ]Specify?
  - A separate framework that provides null-safety annotations: @Nullab
  - Makes null intent explicit ... IDEs catch null issues before runtime
- What's new in Spring Boot 4
  - Spring APIs now annotated with ISpecify (used internally in the framew
  - Specify works across all Spring APIs: controllers, services, repositorie:
- Specify is optional to use ... not a breaking change
## Key Feature #4: Modern HTTP Clients
- RestClient API
  - Cleaner, fluent replacement for RestTemplate (future direction)
- Interface Clients with @HttpExchange
  - Write a simple Java interface then Spring generates the client for you
- Benefits
  - Less boilerplate
  - Easier testing
  - Clearer code than RestTemplate
  - More consistent than writing manual WebClient or RestTemplate calls
## Key Feature #5: Modularization
- What Changed
  - The large spring-boot-autoconfigure JAR is now split into 70+ focused modules
  - Starters now pair with matching test starters (e.g., webmvc + webmvc-test)
- Benefits
  - Loads only what your app needs
  - Faster startup, smaller footprint
- Developer Impact
  - If you are using starters then no changes needed
  - Custom dependency sets should review module names

## Development Process
1) Perform the migration to Spring Boot 4: update pom.xml 
2) In pom.xml, update web starter (replace deprecated)
3) Update Jackson 3 package imports 
4) Inject JsonMapper
5) Update PATCH coding accordingly
### 1. Update pom.xml
```
	<parent>
		<groupId>org.springframework.boot</groupId>
		<artifactId>spring-boot-starter-parent</artifactId>
		<version>4.x.x</version>
		<relativePath/>
	</parent>
```

- Replace below 

## REST API Versioning
- REST APIs evolve over time
- Existing REST clients cannot always upgrade immediately (external etc)
- Spring Boot 4 provides built-in API versioning support
- Goal: support change without breaking existing clients
### Problem
- New features often require breaking changes
- Removing or changing fields can break existing clients
- Multiple client versions may exist at the same time (phased approach)
- We need an easy way to run multiple API versions side by side
### Hello World REST API
- One logical endpoint: /hello
- Three API versions ... version comes from the request path
- No duplicate controllers or manual coding
```
 GET http://localhost: 8080/api/v1/hello
 GET http://localhost: 8080/api/v2/hello
 GET http://localhost: 8080/api/v3/hello
 ```
## Benefits of API versioning
- Declarative API versioning 
- Clean controller code (no special logic, no conditionals)
- Easy to add new versions 
- Minimal impact on existing clients
